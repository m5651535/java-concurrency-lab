# ADR-002：雙層快取架構：Caffeine (L1) + Redis (L2)

## 狀態
已採用

## 背景

第九階段針對 lab-webflux 導入 Caffeine 作為 JVM 本地快取（L1），
Redis 作為分散式快取（L2），期望進一步降低 Redis 網路 RTT 的開銷。

## 決策

採用 L1+L2 雙層快取，但僅在資料集夠大且快取充分預熱後才有顯著效益。

## 理由

1. **Caffeine 省掉 Redis 的網路 RTT**（實測約 14ms），
   在熱點資料高度集中時效果顯著。
2. **長時壓測（含 Cache Warm-up）下**，
   L1+L2 相比純 Redis 吞吐量提升 12%，平均延遲降低 15%。

## Trade-off

- 資料集小時（userId 1~100），Redis 命中率已接近 100%，
  Caffeine 的額外 pipeline 複雜度反而導致效能下降。
- 冷啟動時 L1 無效，必須等快取熱起來才能體現優勢。
- 引入 L1 增加了快取一致性的維護複雜度。

## 結論

L1 快取的效益強烈依賴資料集大小與存取熱度分布。
建議僅在資料集 > 10,000 筆且存取模式符合二八法則時採用雙層架構。
